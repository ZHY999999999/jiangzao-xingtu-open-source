# <roadmap-id> · <一句话标题>

**owner: local** · 报告到本任务的 PR · 破坏性步骤见 §5（没有则写「无」）

## 1. 目标

两三句：现状是什么、要变成什么、为什么现在做。

## 2. 边界

只动哪些文件 / 目录；明确不碰什么；报告里不能出现什么（主机名、IP、密钥路径）。

## 3. 设计

设计师给出的规则、数据结构、命令形态、UI 版式。执行者照此实现，不自定；有异议写进报告「需要决定」。

## 4. 步骤

编号列出，每步给命令或改动位置。标明**停点**：做到第几步发 `## 报告 N`。

## 5. 破坏性步骤

列出哪一步不可逆、需要所有者 `批准：<动作>` 评论；执行前后要记录什么。

## 6. 验收

- [ ] 可核对的条件，一条一行；UI 任务必含「`ui-check` 全部 PASS，contact-sheet 已提交到 docs/tasks/evidence/<id>/」

## 7. 报告模板

```
## 报告 N
验收：
- [x] 条件 — 证据（命令 + 输出摘要 / 哈希 / 文件数）
- [ ] 条件 — 未做 / 原因
阻塞：无
需要决定：无（或：A … / B …（推荐）/ C …）
```
