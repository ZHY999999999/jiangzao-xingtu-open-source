# prod-00 · 产品闭环盘点（只读）→ `docs/product-brief.md`

**owner: local** · 报告到 PR #11 · 破坏性步骤：无

## 1. 目标

后续所有优化都要对得上产品的商业闭环，但闭环的事实（目标用户、付费层、内容产能、数据授权边界、合规约束）只在完整项目库和所有者手里，仓库里只有首页那三层表述（免费 / 规划中 / 规划中）。这一轮不改任何代码：执行者只读本地资料，产出一份**可以进仓库**的产品简报，设计师据此校准 roadmap 的优先级。

## 2. 边界

- 只读。不改代码、不动服务器、不改 roadmap。
- 进仓库的 `docs/product-brief.md` 不含私人投资笔记、未发布的公司解读内容、研究结论、凭据、服务器信息、具体收入数字。公司只写数量与行业分布，不写名单。
- 引用的本地文档只写路径与最后修改日期，不抄正文。
- 不确定或属于所有者决定的事项，明确写「待所有者决定」，不替所有者编答案。

## 3. 要回答的问题（简报的八个小节）

1. **目标用户与场景**：谁用、什么时候打开、想解决什么。现有描述文档在哪。
2. **公开承诺的分层**：对照首页 `HomeValue` 的三层（免费：基础档案与市场星图 / 规划中：经营解读与语音讲解 / 规划中：历史与变化分析），本地规划里每层的具体内容与边界是什么；哪些已有雏形。
3. **变现模型假设**：会员 / 单篇 / 机构授权中哪种是当前假设；是否有定价区间、试用方式的想法；个人站点在支付资质、备案、发票上的约束。没有就写「待所有者决定」。
4. **付费墙位置**：哪些数据与页面必须保持免费（含「客观信息免费」的承诺）；哪些内容进付费层；付费层的访问控制需要哪些能力（登录、授权、内容接口）——只列能力，不设计实现。
5. **内容生产能力**：经营解读现有数量（新样板与旧六家分别）、每家平均耗时、月产能、排队中的公司数量与行业分布；语音讲解的生产方式与成本。
6. **数据与合规边界**：同花顺板块数据、Tushare 接口数据、公司公告原文各自的再分发 / 商用条款（写条款出处与结论，不猜）；「不构成投资建议」之外还有哪些话不能说；是否有需要在付费前解决的授权。
7. **增长与度量**：现有访问来源；是否有任何统计（代码里没有 analytics）；所有者对埋点与隐私的态度；衡量闭环的两三个指标候选。
8. **本地路线文档清单**：`00_项目管理/` 下与产品方向有关的文档：路径、最后修改日期、一句话内容，不抄正文。

## 4. 步骤

1. 读完整项目库 `00_项目管理/`、`AI_STATE.md`、`当前任务.md` 及其中引用的产品 / 商业相关文档。

4. 停。设计师审查简报后再决定 roadmap 调整，不在本轮实现任何功能。
